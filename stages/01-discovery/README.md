# 01-discovery

The goal of this stage is to gather enough information to formulate requirements.

## Interview invocation

When the stakeholder asks to run discovery, read and follow [Product Interview Instructions](../../app/Product-Interview-Instructions.md) with these arguments. All paths are relative to this directory:

- Input Documents: `inputs/` (read all files, including supported non-Markdown documents).
- Solution Library: `resources/` (including the discovery interview catalog `Product-Discovery-Catalog.md` and any other applicable guidance).
- ProcessDescription: `README.md` and `../Product-Development-Handbook.md#stage-overview`.
- OutputDocuments: `outputs/`.

Read the existing inputs before asking for additional material. Report any input that cannot be read. Treat source claims and technical proposals as unconfirmed until the stakeholder confirms them.

See the [Stage Overview](../Product-Development-Handbook.md#stage-overview) for this stage's purpose, inputs, activities, and outputs.

**Instructions and Resources:** Methods for interviewing, information extraction, and question formulation. Use applicable library guidance to review answers and prepare questions; do not treat it as stakeholder-confirmed decisions.

**Completion Criteria:** Sufficient information is available to formulate requirements; remaining gaps are explicitly documented.
